Greedily for each bit, in order to fill that bit we need to find the minimum operations needed for some $v[i]$ in order to fill that bit. This thus turns into a problem in $x-1$ bits, in which we can repeat the process until $k$ runs out. To find out which $x$ bit needs to be filled, we must update this while performing operations.

Let $x$ be lower bound and $y$ be upper bound. Let $cnt[x]$ be number of elements in original array $<= x$ and $cnt[y]$ be number of elements in original array $>=y$. These numbers then gets turned into $x$ and $y$ in the end. Let $op[x]$ and $op[y]$ be the number of operations needed to make them this way.
In the end if $op[y]>op[x]$, this means we need to fill. Then it must be that after, we have $op[x]$ operations to make everything be in between lower and upper bound, then the remaining $op[y]-op[x]$ operations must be to fill $x$ to $x+1$, since it will be smallest (if $op[y]-op[x]$ is enough to fill all $cnt[x]$, then $x$ can't be the minimum anymore). Similarly if $op[x] > op[y]$, the extra $op[x]-op[y]$ operations is used to make $y$ be $y-1$, since we need them in order to fill in the extra to make $x-1$ to $x$ and thus satisfy the minimum.

Thus, for some optimal $x$ and $y = x+k$, if $op[y]>op[x]$, the first $cnt[x] - (op[y]-op[x])$ elements is $x$, then the remaining (of the first $cnt[x]$ elements) is $x+1$.
If $op[x] > op[y]$, then the last $cnt[y] - (op[x]-op[y])$ elements is $y$, and the remaining (of the last $cnt[y]$) is $y-1$. 
Then, answer is $\sum_{i=1}^{n}\frac{(a[i])\cdot(a[i]+1)}{2} + (max(op[x],op[y])\cdot k$ for each element and finish.
If we find $x$, we can find $y$ by $y = x+k$. To find what $op[x]$ is and what $x$ is, if $op[y]>op[x]$, then we have $op[y]-op[x]$ cars that needs to go to the left. However if this is more than $cnt[x]$, then our answer is forced to be $x+1$ or higher. Thus, we check if $op[y]-op[x] > cnt[x]$. If it is then we know the minimum must be larger, so we set lo = x+1.
